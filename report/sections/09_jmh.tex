\section{JMH Micro-Benchmarks (Java only)}
\label{sec:jmh}

The end-to-end harness measures whole operations. To see where the Java
implementation spends its time inside those operations, the port carries
four JMH micro-benchmark classes (six measurements) over its hot paths
(\texttt{multilang\_ports/java/src/main/java/microbench/}).

\paragraph{Configuration.}
JMH 1.37 on OpenJDK 21.0.13, average-time mode, 1 thread, 1 fork, 5+5
iterations of 1~s (warm-up and measurement), GC profiler enabled. Unlike the
harness phases, JMH is \emph{not} pinned: \texttt{run\_jmh.sh} starts the
shaded jar without \texttt{taskset} and without JVM flags, so it runs with
the JVM's default ergonomics on all logical cores, and its absolute numbers
are not comparable with the pinned end-to-end Java figures. Raw JSON:
\texttt{benchmarks\_\allowbreak results/java/\allowbreak jmh\_\allowbreak results.json},
produced by \texttt{multilang\_\allowbreak ports/java/\allowbreak run\_\allowbreak jmh.sh}.

\paragraph{What changed and what it shows.}
Serialising the JSON index now costs $5.5\times$ parsing it ($4.4\times$
before): since the current snapshot \texttt{saveIndex} writes through the
temporary-file, \texttt{fsync} and rename path, so the benchmark includes
that synchronisation, its time rose 15\% and its allocation per operation
rose from 19.2 to 155.5~MB. \texttt{buildPostings} over 100 books has a
confidence half-width larger than its score (2484.8 $\pm$ 2564.5~ms): with
five measured iterations in one fork, individual iterations differ by
seconds, consistent with collection pauses in the \texttt{TreeSet}-based
builder identified in \cref{sec:index-scalability}; a reliable figure needs
more forks and iterations. The other four scores moved by 2--8\%, within what
one fork on an unpinned host can resolve.

\paragraph{How these numbers may be used.}
They explain the \emph{internal} split of one Java operation, which helps
attribute the end-to-end Java bars of \cref{sec:index}: postings
construction, not serialisation or querying, is the Java hot path that grows
with the input. They are \textbf{evidence about the Java port only}: JMH's
forked-JVM warm-up protocol is deliberately \emph{not} applied to the other
languages, so no JMH number is ever placed next to a Python, Go or Rust
measurement in this report. The cross-language figures of
\cref{sec:language-performance} all come from the common harness of
\cref{sec:methodology}.
